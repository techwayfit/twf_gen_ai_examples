## Overview

This application supports two types of embedding generation for code indexing and semantic search:

1. **API-Based (OpenAI)** - Cloud service that generates high-quality embeddings via REST API
2. **Local (ElBruno.LocalEmbeddings)** - On-device embedding generation using ONNX Runtime

Both options implement the same interface, allowing seamless switching via configuration.

## API-Based Embeddings (OpenAI)

### What is it?

OpenAI embeddings are generated by sending your text to OpenAI's servers, which return a high-dimensional vector (1536 or 3072 dimensions) representing the semantic meaning of the text.

### Advantages

✅ **Superior Quality** - State-of-the-art embeddings trained on massive datasets
✅ **Zero Setup** - Just add API key
✅ **Always Up-to-Date** - OpenAI maintains and improves models
✅ **Multiple Models** - Choose between `text-embedding-3-small` (1536d) and `text-embedding-3-large` (3072d)
✅ **Scalability** - No local compute resources needed

### Disadvantages

❌ **Costs Money** - Pay per token processed (~$0.00013 per 1K tokens)
❌ **Requires Internet** - Cannot work offline
❌ **Privacy Concerns** - Your code is sent to OpenAI servers
❌ **Rate Limited** - Can hit API limits with large codebases
❌ **Latency** - Network round-trip adds 100-500ms per request
❌ **Vendor Lock-in** - Dependent on OpenAI availability

### Technical Details

- **Model**: `text-embedding-3-small` (default) or `text-embedding-3-large`
- **Dimensions**: 1536 or 3072
- **Max Input**: 8191 tokens per request
- **Protocol**: HTTPS REST API
- **Authentication**: Bearer token (API key)

## Local Embeddings (ElBruno.LocalEmbeddings)

### What is it?

Local embeddings use ONNX Runtime to run a sentence transformer model (`sentence-transformers/all-MiniLM-L6-v2`) directly on your machine. No data ever leaves your computer.

### Advantages

✅ **100% Free** - No per-use costs after initial download
✅ **Privacy First** - Your code never leaves your machine
✅ **Blazing Fast** - 5-50ms per embedding (10-50x faster than API)
✅ **Offline Ready** - Works without internet (after model download)
✅ **No Rate Limits** - Process as many texts as your CPU can handle
✅ **Predictable Performance** - No network variability
✅ **No Vendor Lock-in** - Open-source model and library

### Disadvantages

❌ **Lower Quality** - Good but not as good as OpenAI's largest models
❌ **Fixed Model** - Default is 384 dimensions (vs 1536/3072)
❌ **Initial Download** - ~90-100 MB model download on first use
❌ **CPU/Memory Usage** - Requires local compute resources
❌ **Model Cache** - Takes up disk space (~100 MB)

### Technical Details

- **Model**: `sentence-transformers/all-MiniLM-L6-v2` (default)
- **Dimensions**: 384
- **Max Input**: 512 tokens per request
- **Runtime**: ONNX Runtime (CPU)
- **Library**: ElBruno.LocalEmbeddings v1.5.0
- **Cache Location**: 
  - Windows: `%USERPROFILE%\.cache\huggingface\`
  - Linux/Mac: `~/.cache/huggingface/`

## Configuration Guide

### Prerequisites

Both providers are already included in the project:
- ✅ OpenAI API client (via `LlmService`)
- ✅ ElBruno.LocalEmbeddings NuGet package

### Step-by-Step Configuration

#### Option 1: Using OpenAI (API-Based)

**1. Edit `appsettings.local.json`:**

```json
{
  "Embeddings": {
	"Provider": "OpenAI",
	"EmbeddingDimension": 1536
  },
  "OpenAI": {
	"ApiKey": "sk-proj-your-actual-api-key-here",
	"ChatModel": "gpt-4o-mini",
	"EmbeddingModel": "text-embedding-3-small",
	"Endpoint": "https://api.openai.com/v1"
  }
}
```

**2. Get Your API Key:**
- Go to https://platform.openai.com/api-keys
- Create a new API key
- Replace `sk-proj-your-actual-api-key-here` with your key

**3. Choose Your Model:**

| Model | Dimensions | Performance | Cost | Best For |
|-------|-----------|-------------|------|----------|
| `text-embedding-3-small` | 1536 | Better | Lower | Most cases |
| `text-embedding-3-large` | 3072 | Best | Higher | Maximum quality |
| `text-embedding-ada-002` | 1536 | Good | Medium | Legacy apps |

**4. Update Dimensions:**

If using `text-embedding-3-large`:
```json
{
  "Embeddings": {
	"EmbeddingDimension": 3072
  }
}
```

**5. Restart the application**

#### Option 2: Using Local Embeddings

**1. Edit `appsettings.local.json`:**

```json
{
  "Embeddings": {
	"Provider": "Local",
	"EmbeddingDimension": 384
  },
  "LocalEmbeddings": {
	"ModelPath": "",
	"EmbeddingDimension": 384
  }
}
```

**2. No API Key Needed!** ✅

**3. Restart the application**

**4. First Run:**
- The model will download automatically (~90-100 MB)
- This happens only once
- Progress shows in console
- Subsequent runs are instant

## Switching Between Providers

### ⚠️ IMPORTANT: Re-Indexing Required

When switching between providers, you **must re-index your codebase** because:

1. **Different Dimensions**: OpenAI uses 1536 dims, Local uses 384 dims
2. **Incompatible Vector Spaces**: Vectors from different models cannot be compared
3. **Qdrant Schema**: The vector database schema is locked to the first embedding dimension used

### Step-by-Step Switch Process

#### Switching from OpenAI → Local

**Step 1: Update Configuration**

Change `appsettings.local.json`:
```json
{
  "Embeddings": {
	"Provider": "Local",      // Changed from "OpenAI"
	"EmbeddingDimension": 384  // Changed from 1536
  }
}
```

**Step 2: Clear Existing Index (if using Qdrant)**

If you configured Qdrant:
```bash
# Delete the collection via Qdrant API or UI
# Or change the collection name in appsettings:
```

```json
{
  "Qdrant": {
	"CollectionName": "repo-code-index-local"  // New name
  }
}
```

**Step 3: Restart Application**

```bash
dotnet run
# Or press F5 in Visual Studio
```

**Step 4: Re-Index Your Codebase**

1. Open the application UI
2. Go to the Indexing tab
3. Select your repository folder
4. Click "Index Repository"
5. Wait for indexing to complete

#### Switching from Local → OpenAI

**Step 1: Get OpenAI API Key**

Get your key from https://platform.openai.com/api-keys

**Step 2: Update Configuration**

```json
{
  "Embeddings": {
	"Provider": "OpenAI",
	"EmbeddingDimension": 1536
  },
  "OpenAI": {
	"ApiKey": "sk-proj-your-key-here"
  }
}
```

**Step 3: Clear Qdrant Collection (if used)**

Change collection name or delete existing:
```json
{
  "Qdrant": {
	"CollectionName": "repo-code-index-openai"
  }
}
```

**Step 4: Re-Index**

Follow the same re-indexing steps as above.

## Cost Analysis

### Example: Indexing a Medium Project

**Project Size**: 200 files, 50,000 lines of code
**Chunks Generated**: ~500 code chunks (avg 150 tokens each)
**Total Tokens**: ~75,000 tokens

#### OpenAI Costs

| Model | Cost per 1M tokens | Cost for Project | Monthly (10 indexes) |
|-------|-------------------|------------------|---------------------|
| `text-embedding-3-small` | $0.02 | $0.0015 | $0.015 |
| `text-embedding-3-large` | $0.13 | $0.0098 | $0.098 |

**Annual Costs** (assuming 120 re-indexes/year):
- Small model: ~$0.18/year
- Large model: ~$1.18/year

#### Local Embeddings Cost

| Cost Type | Amount |
|-----------|--------|
| Per embedding | $0.00 |
| Per project | $0.00 |
| Monthly | $0.00 |
| Annual | $0.00 |

**Electricity Cost** (negligible):
- CPU power: ~15W during embedding
- 500 embeddings @ 20ms each = 10 seconds
- Cost: < $0.0001

### When Does OpenAI Become Expensive?

OpenAI costs scale linearly. It becomes significant when:

- 🔴 Indexing 50+ large projects/month: ~$5-20/month
- 🔴 Frequent re-indexes (CI/CD pipeline): Can add up
- 🔴 Real-time embedding of user queries: High volume can be costly
- 🟢 Small teams, occasional indexing: < $1/month

## Use Cases & Recommendations

### ✅ Use OpenAI When:

- 🎯 **Production applications** requiring maximum quality
- 🎯 **Low-frequency indexing** (once per week/month)
- 🎯 **Critical semantic search** where accuracy matters most
- 🎯 **Small codebases** (< 100 files)
- 🎯 **Team has OpenAI budget** allocated
- 🎯 **Privacy is not a concern** (using public/open-source code)

### ✅ Use Local Embeddings When:

- 🎯 **Development & testing** environments
- 🎯 **Frequent re-indexing** (multiple times daily)
- 🎯 **Large codebases** (1000+ files)
- 🎯 **Privacy-sensitive code** (proprietary, confidential)
- 🎯 **Air-gapped environments** (no internet access)
- 🎯 **Cost-conscious** projects (hobbyist, educational)
- 🎯 **Offline work** (traveling, unreliable internet)
- 🎯 **CI/CD pipelines** (automated indexing)

### 🔀 Hybrid Approach

**Best of Both Worlds:**

```json
{
  "Development": {
	"Provider": "Local"
  },
  "Production": {
	"Provider": "OpenAI"
  }
}
```

Use environment-specific configuration files:
- `appsettings.Development.json` → Local
- `appsettings.Production.json` → OpenAI

## Troubleshooting

### OpenAI Issues

#### ❌ "API key not configured"

**Problem**: Missing or invalid API key

**Solution**:
```json
{
  "OpenAI": {
	"ApiKey": "sk-proj-actual-key-not-placeholder"
  }
}
```

Restart the application after updating.

#### ❌ "Rate limit exceeded"

**Problem**: Sending too many requests to OpenAI

**Solution**:
1. Wait 60 seconds and retry
2. Reduce batch size in indexing
3. Upgrade OpenAI plan for higher limits
4. Switch to Local embeddings temporarily

#### ❌ "HTTP 429 Too Many Requests"

**Problem**: OpenAI rate limits

**Solution**:
```json
{
  "Indexing": {
	"MaxChunkTokens": 800,  // Increase chunk size
	"MaxFiles": 100         // Index fewer files
  }
}
```

This reduces the number of API calls.

### Local Embeddings Issues

#### ❌ "Model not found"

**Problem**: Model not downloaded yet

**Solution**:
1. Ensure internet connection for first run
2. Wait for automatic download (~2-5 minutes)
3. Check console for download progress
4. Verify cache directory exists and is writable

#### ❌ Slow first startup

**Problem**: Model downloading

**Solution**: This is normal! Wait for:
```
Downloading model: sentence-transformers/all-MiniLM-L6-v2
Progress: [████████░░] 80% - 82MB/102MB
```

Subsequent starts are instant.

#### ❌ "Out of memory"

**Problem**: System running low on RAM during embedding

**Solution**:
1. Close other applications
2. Reduce concurrent embeddings:
   ```json
   {
	 "Indexing": {
	   "MaxFiles": 50  // Process fewer files at once
	 }
   }
   ```

#### ❌ Embeddings seem low quality

**Problem**: Local model has limitations

**Solution**: Switch to OpenAI for better quality:
```json
{
  "Embeddings": { "Provider": "OpenAI" }
}
```

## FAQ

### Can I use both providers simultaneously?

No, the application uses one provider at a time based on configuration. However, you can switch anytime by changing `Embeddings:Provider`.

### Do I need to re-index when switching providers?

**Yes, always.** Different providers produce incompatible vectors (different dimensions and semantic spaces).

### What happens to my API key with Local embeddings?

It's ignored. The application doesn't make API calls when using Local provider.

### Can I use Azure OpenAI instead of OpenAI?

Not currently, but you can extend `OpenAIEmbeddingService` to support Azure endpoints. Change the `Endpoint` configuration.

### How much disk space does the local model need?

~100 MB for the default model (`all-MiniLM-L6-v2`).

### Can I delete the local model cache?

Yes, delete:
- Windows: `%USERPROFILE%\.cache\huggingface\`
- Linux/Mac: `~/.cache/huggingface/`

The model will re-download on next use.

### Is the local model as good as OpenAI?

No. OpenAI models are larger and more accurate (~7-10% better). But local models are good enough for most code search tasks.

### Can I use different local models?

Currently, the default model is hardcoded. You can modify `LocalEmbeddingService.cs` to support custom models. See the [ElBruno.LocalEmbeddings documentation](https://github.com/elbruno/elbruno.localembeddings).

### Does local embedding work on Mac/Linux?

Yes! ONNX Runtime is cross-platform. The library works on:
- ✅ Windows (x64, ARM64)
- ✅ macOS (Intel, Apple Silicon)
- ✅ Linux (x64, ARM64)

### What if I'm behind a corporate proxy?

**For OpenAI**: Configure proxy in `HttpClient`:
```csharp
builder.Services.AddHttpClient("openai")
	.ConfigurePrimaryHttpMessageHandler(() => new HttpClientHandler
	{
		Proxy = new WebProxy("http://proxy.company.com:8080"),
		UseProxy = true
	});
```

**For Local**: No internet needed after first download.

### Can I use this in production?

**Yes**, both providers are production-ready:
- **OpenAI**: Enterprise-grade service with 99.9% uptime
- **Local**: Stable ONNX Runtime, used in production by many companies
